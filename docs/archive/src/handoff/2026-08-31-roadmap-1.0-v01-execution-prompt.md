# 0. Regola principale

NON partire creando issue alla cieca.

Prima devi verificare lo stato reale del repository e di GitHub.

Ordine obbligatorio:

```text
Repository audit
    ↓
GitHub audit OPEN + CLOSED
    ↓
Mappa esistente → roadmap
    ↓
REUSE / UPDATE / CREATE
    ↓
Collega Epic / milestone / dipendenze
    ↓
Implementa la prima issue v0.1 non completata e non bloccata
    ↓
Build + Automation + packaged gate
```

Non duplicare issue esistenti.

Se una issue esistente copre il 70–100% dell'outcome:
- riusala;
- aggiornane body / DoD se necessario;
- non crearne una seconda.

Se una issue è parzialmente sovrapposta:
- classificala `PARTIAL_OVERLAP`;
- decidi se estenderla o creare una issue complementare;
- documenta la scelta.
