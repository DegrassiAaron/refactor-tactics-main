REFACTORTACTICS — AFFINITY ICON LIBRARY ROADMAP v0.1 → v1.0

CONTENTS
One cumulative Affinity-ready SVG template per release:
v0.1, v0.2, v0.3, v0.4, v0.5, v0.6, v0.7, v0.8, v0.9, v1.0.

HOW TO USE
1. Start with v0.1.
2. Open the SVG in Affinity Designer and Save As .afdesign.
3. Convert each MASTER_24__MAKE_SYMBOL group to an Affinity Symbol.
4. Use Symbol instances in REFERENCE_INSTANCES and QA boards.
5. When moving to the next release, open its cumulative template.
6. Layers marked NEW_THIS_VERSION are the new production/QA scope.
7. Layers marked INHERITED_vX.Y are carried from previous milestones.
8. OPTICAL_16 is a separate Symbol only when true optical simplification is required.

IMPORTANT
- These templates follow the HUD/UI roadmap, not a fabricated new release plan.
- For runtime Semantic IconIds, the live repository remains authoritative.
- v0.1 RequiredIconIds must be remeasured from the code before asset import.
- E20 = v0.1 minimum icon-language foundation.
- E25 = v0.2 complete icon-language continuation.
- Later templates add HUD/UI consumer needs and QA scope from the consolidated v0.1→v1.0 roadmap.
- Items explicitly marked ONLY if gameplay currently supports them must not be treated as new gameplay requirements.

SHARED SHAPE GRAMMAR
Core = most important information
Hexagon = intrinsic target/element/usage/geometry
Circle = cost/cooldown/charges/use limit
Square = external active modifier
Diamond = skill modifier
Triangle = condition/trigger/requirement/warning
